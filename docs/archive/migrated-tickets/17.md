## Original issue body

## Problem

Meeting rooms are billed on metered 8x8 usage. The operator is happy to pay for scheduled group meetings but not for moderators using the platform personally afterwards. Today a room is opened by a one-off window (#7); to run a weekly writers' group the operator must create a fresh window every week, and there is no way to express "every Tuesday at 19:00 UTC for 4 hours."

This issue lets the room registry express **recurring meeting definitions** while keeping its last-row-wins model: the latest row for a room is its authoritative definition, and that row may now describe a repeating schedule instead of a single window. The guest gate then admits participants only during a current occurrence.

Target definitions (all UTC, all defaulting to a 4-hour window opening 15 minutes early):

- `2026-08-09T18:00:00Z` fortnightly (every second week from that anchor)
- the first Wednesday of every month at 18:00:00 UTC
- the second Tuesday of every month at 20:30:00 UTC

## Scope and relationship to metered cost

This issue bounds **guest** access to scheduled occurrences. It does **not** change moderator access: a valid moderator token still bypasses the window entirely (the accepted behaviour of AC7.6 / RT-12.11). So recurring slots alone do not stop a moderator opening a room off-schedule and incurring metered minutes. Bounding moderator access to active windows is #14's job ("gate the moderator entry on active-now"); once #14 lands, "active now" will mean "inside a current occurrence." The two issues together meet the cost goal; this one is the schedule half. Reconsidering the moderator JWT window-bypass is out of scope here.

## Assumptions (confirm at PROCEED)

- All times are UTC; DST is not handled, so a UTC-anchored slot's local wall-clock time shifts by an hour across a DST change.
- Recurrence kinds: weekly, every-N-weeks (fortnightly is N=2), and monthly Nth-weekday.
- Default occurrence duration and early-open lead come from the application config YAML (not hardcoded in source) and are overridable per room.
- Occurrence length is set with `--duration`, and the early-open lead with `--open-early`, both accepting a compound value: a number, or a colon-split pair, followed by a unit suffix `h`/`hour`, `m`/`min`, or `s`/`sec`. A colon splits the value into that unit and the next-smaller one, e.g. `4:30h` = 4h30m, `90:00 min` = 90m, `45s` = 45s.
- A series runs indefinitely until cancelled, with an optional end via `--ends`.
- `--until` (the one-off window end from #7) is deprecated in favour of `--from` + `--duration`, but remains accepted for backward compatibility. The series terminator is the distinct `--ends`, so the `--until` meaning is not overloaded.
- One-off windows (#7) continue to work unchanged.

## Usage examples

```
# Fortnightly from an anchor, config-default 4h window opening 15m early
meet create --room writers --from 2026-08-09T18:00:00Z --repeat fortnightly

# First Wednesday of every month at 18:00 UTC (config-default window)
meet create --room board --repeat monthly --ordinal 1 --weekday wed --at 18:00

# Second Tuesday of every month at 20:30 UTC, 90-minute window
meet create --room critique --repeat monthly --ordinal 2 --weekday tue \
  --at 20:30 --duration 90:00min

# Weekly, 4.5h window, series ends at year's end
meet create --room workshop --from 2026-09-01T19:00:00Z --repeat weekly \
  --duration 4:30h --ends 2026-12-31

# One-off using the new --duration form (replaces --until)
meet create --room demo --from 2026-08-20T14:00:00Z --duration 2h
```

## Solution Design

### Recommended approach

Extend the existing room registry (`internal/server/roomslog.go`) and the guest gate (`internal/server/server.go`) rather than adding a new store. The last-row-wins model and the `created`/`cancelled` statuses are unchanged; a `created` row gains an optional recurrence definition.

**Registry row.** Add a recurrence specification to `RoomLogEntry`, serialized as additional CSV columns appended after `note` (old six-column rows decode as one-off, since `decodeEntry` already tolerates variable field counts via `FieldsPerRecord = -1`). Proposed columns: `recur_kind` (empty | `weekly` | `nweekly` | `monthly`), `recur_interval_weeks`, `recur_ordinal`, `recur_weekday`, `recur_time` (HH:MM UTC), `duration_seconds`, `lead_seconds`, `recur_ends`. For weekly/nweekly, `valid_from` is the anchor occurrence (its weekday and time-of-day drive the series); for monthly, `valid_from` is the series start and `recur_ordinal`/`recur_weekday`/`recur_time` define the occurrence. `recur_kind` empty means a one-off row (existing behaviour). `duration_seconds` and `lead_seconds` are resolved at create time (from flags or the config defaults) and stored concretely, so the gate reads a self-contained row and does not depend on config.

Store the recurrence as **explicit typed fields/columns, not a packed rule string parsed by regex** (CODING.md "Data Handling": format-aware parsing, no line-based parsing of structured data).

**Occurrence computation.** Add pure, UTC-only functions (deterministic, no wall-clock reads) that, given a recurrence and a `now`, return whether `now` falls in a current occurrence's `[start - lead, start + duration]` window:
- weekly / nweekly: occurrences at `anchor + k * intervalWeeks * 7d`; find the occurrence whose window can contain `now`.
- monthly Nth-weekday: for the month of `now` (and the adjacent month for boundary safety), compute the Nth weekday at the time-of-day; a month lacking that Nth weekday contributes no occurrence.
Boundaries are inclusive, matching the existing one-off gate (`!now.Before(start-lead) && !now.After(start+duration)`).

**Gate.** Refactor the active-now decision (used by `gateAllows`, and by #14's `roomActiveNow` if that lands) so it consults recurrence for a recurring row and the existing `[valid_from, valid_until]` for a one-off row. Tests drive it through the guest HTTP boundary with the injected clock (`Config.Now`), exactly as the #7 and #13 gate tests do.

**CLI.** Extend `create` (`cmd/meet/main.go`) with: `--repeat weekly|fortnightly|monthly`, `--weekday`, `--ordinal` (monthly), `--at HH:MM` (UTC time-of-day), `--duration` (occurrence length, compound format), `--open-early` (lead, compound format), and `--ends` (series end date). `--from` supplies the anchor for weekly/fortnightly. When `--duration`/`--open-early` are omitted, the config defaults are used. Validate combinations and reject invalid weekday/ordinal/duration before writing.

`--until` is kept as a deprecated alias for the one-off window end (so #7's CLI and tests are unaffected), and `--duration` is the preferred way to express a one-off length as `--from` + `--duration`. The series terminator is the distinct `--ends`.

**Configuration.** Add default duration and early-open lead to the config YAML (e.g. under a `meeting:` key: `default-duration`, `default-open-early`), loaded through the existing config cascade that `create` already reads. These are create-time defaults only; the gate uses the concrete values stored on each row.

**Duration parsing.** Add an exported duration parser in `internal/server` (so both the CLI and any config loading reuse it and it is unit-testable). Grammar: an integer, or `A:B`, followed by a unit `h`/`hour`, `m`/`min`, `s`/`sec` (optional space before the unit). A colon splits into that unit plus the next-smaller one (`h`→minutes, `m`→seconds); `s` takes no colon. The minor field must be 0..59. The result must be positive. Reject anything else with a clear error.

### Patterns to follow

- stdlib `time` for all date arithmetic; UTC throughout (GO.md "Standard Library Preference").
- Extend the CSV tolerantly, preserving `decodeEntry`'s variable-length handling and last-row-wins reads.
- Injected clock (`Config.Now`) for deterministic occurrence tests, as in the existing registry gate tests.
- Reuse the #13 inactive-room response for the closed-window case; no new guest response.

### Anti-patterns to avoid

- Do not encode the recurrence as a mini-language string parsed with regex or line splitting (CODING.md "Data Handling"); use explicit columns/fields and typed parsing.
- Do not read the real wall clock inside occurrence math; take `now` as a parameter so it is testable (CODING.md "Prohibited Anti-Patterns": global/hidden state).
- Do not change the moderator JWT bypass here; that is #14's scope.
- Do not silently swallow parse errors in occurrence computation; a malformed row is skipped with a logged reason, not treated as active.
- Tests must exercise the guest HTTP boundary and the CLI entry point, not grep source (TESTING.md "The real-user test").

### Test plan and locations

- `tests/regression/recurrence_test.go`: RT-17.1 through RT-17.12, RT-17.17 through RT-17.25, RT-17.30, RT-17.31 (registry and guest gate with the injected clock through `httptest`), and RT-17.34 through RT-17.38 (the exported duration parser, unit-tested directly).
