## Original issue body

## Problem

`meet` is now a NixOS-only deployment. The Ubuntu deployment target is no longer supported for production.

Issue #8 introduced a useful general helper shape: `meet-helper <host> <subcommand> [args...]` forwards arbitrary `meet` subcommands over SSH with shell-safe argument handling. The implementation was written against the legacy Ubuntu deploy-app filesystem layout, embedding paths such as `/srv/meet/meet`, `/srv/meet/repo/config/...`, and `/etc/meet/secrets.yaml`.

The current NixOS deployment contract says app code and helper scripts must not embed host filesystem paths for config, secrets, state, or binary locations. One-off admin CLI commands are exposed through the generated `APP-admin` wrapper on the host:

```bash
ssh HOST 'sudo -u APP APP-admin SUBCOMMAND [args...]'
```

For `meet`, the helper must call the `meet-admin` wrapper as the `meet` app user and let deploy-nix supply the app identity, working directory, config, secrets, state directory, and runtime environment.

After production deployment testing began, the operator scheduling workflow exposed two ergonomics gaps: requiring full RFC3339 timestamps for every room is too cumbersome for normal use, and help output must be useful without requiring remote secrets/config loading. Date-only input should be accepted for common cases, all-day rooms should have a first-class shortcut, and every command/subcommand help page must come from the canonical docs/help source.

## Existing implementation state

Already implemented before this issue:

- `meet create`, `meet cancel`, and `meet list` exist.
- Registry state uses `STATE_DIRECTORY` when present.
- `meet-helper` forwards arbitrary subcommands and arguments safely through SSH.
- `meet-helper` help text is sourced from `docs/help/meet-helper.txt`.
- The legacy `meet-token` binary and install target were removed by #8.

Changed for this issue:

- `meet-helper` now builds remote commands as `sudo -u meet meet-admin <subcommand> [args...]`.
- `meet-helper` no longer emits `--config` or any hardcoded config/secrets/binary paths.
- `docs/help/meet-helper.txt` now describes the NixOS deploy-nix admin-wrapper contract.
- The helper regression tests now assert the admin-wrapper command shape and reject embedded deployment paths.
- `meet create --from/--until` now accepts either full RFC3339 timestamps or `YYYY-MM-DD` date-only values; date-only values are interpreted as `00:00:00Z`.
- `meet create --on YYYY-MM-DD` now registers an all-day room from `00:00:00Z` through `23:59:59Z` for that date.
- `meet create --on` is mutually exclusive with explicit `--from` / `--until` bounds.
- `meet-helper <host> <subcommand> --help` now uses the local companion `meet` binary's subcommand help instead of opening SSH.
- Top-level and per-subcommand help prose is canonical in `docs/help/`; code embeds only staged ignored copies and test checks derive help expectations from docs.
- `token` help now explains that the token is the moderator access link/JWT and should be kept separate from the plain guest room URL.

## Solution outline

Retarget the helper to the deploy-nix admin wrapper while preserving the #8 operator interface.

- Keep `meet-helper <host> <subcommand> [args...]` as the local command.
- Keep SSH as the transport and preserve stdout/stderr/stdin streaming.
- Replace direct remote binary invocation with the NixOS admin-wrapper form:
  `sudo -u meet meet-admin <subcommand> [args...]`.
- Keep existing shell quoting for every remote argument.
- Update helper docs to describe the NixOS wrapper contract rather than config cascades or host paths.
- Preserve #8's old-binary removal checks as regression protection, not as a standalone product requirement.
- Limit broad repository scans to tracked project source/docs and exclude agent scratch directories so historical review artefacts cannot block the production regression pack.
- Parse meeting create bounds through a shared helper that first accepts RFC3339 and then falls back to `YYYY-MM-DD` as midnight UTC.
- Add a separate `--on` flag for the common all-day meeting case; derive start/end bounds rather than requiring the operator to type both timestamps.
- Reject mixed `--on` plus `--from` / `--until` invocations so the CLI has one clear source of truth for the meeting window.
- Treat help as local operator documentation: `meet-helper -h` shows the helper page, and `meet-helper <host> <subcommand> --help` shows the local `meet <subcommand> --help` page without SSH or remote secrets/config loading.
- Keep canonical help prose in `docs/help/meet.txt`, `docs/help/meet-<subcommand>.txt`, and `docs/help/meet-helper.txt`; staged embedded copies are generated by the build and ignored by git.
