** Outcome
- Published source supports *direct Go builds* of both commands.
** Before
- Builds require *untracked help copies* generated by Make or test setup.
** After
- A *fresh checkout builds* without staging; help output remains unchanged.
** Changes
- Embed canonical text in one Go package; remove staging and obsolete ignores.
- Retire the help-source grep test; retain behavioural CLI tests.
- Expose the existing Go security scanner through =make vulncheck=.
** Unchanged
- Help wording, output streams, exit status, CLI routing and remote execution.
** Edge cases
- Missing canonical text still causes a *build failure*.
- Helper help remains local, including host-prefixed help flags.
** Decisions
- Use *direct embedding* under =docs/help/= with no generator or runtime reads.

- Publish the verified tag for deployment retry; retain user acceptance as pending.

* Edge Cases
Missing canonical text must fail compilation rather than silently omit help.
No-argument and host-only helper calls retain non-zero usage exits.
These cases retain existing CLI behaviour under AC023.2 - CLI compatibility.

* Solution Design
** Package and build flow
=docs/help/help.go= declares package =helptext= and embeds all seven tracked
text files as strings. Both command packages import it and print the corresponding
string at their existing call sites. There are no runtime file reads.

Make build, test and lint no longer depend on =stage-help-text=. Regression
binary builders call Go directly. The generated-copy ignore rules are removed.
Existing local generated copies are moved recoverably to temporary storage.

** Design verification
Review import direction and embed-to-file mappings once. Verify actual builds
and CLI output through the acceptance commands rather than source-text searches.
The security target invokes the installed =govulncheck ./...= without installing
tools or changing manifests.

** Security impact
No trust, authentication, network, secrets or runtime state boundary changes.
The package contains only public help prose. No new dependency is introduced.
