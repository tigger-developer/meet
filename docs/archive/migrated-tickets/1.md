## Original issue body

## Problem

Meeting recordings, transcriptions, and chat logs are uploaded to 8x8 infrastructure after a session ends. The pre-authenticated download URLs (delivered via webhooks) expire after 24 hours. Without automation, these must be manually retrieved from the 8x8 dashboard before the links expire — a process that is easy to forget and results in lost data.

Transcriptions are particularly valuable as they include speaker attribution (participant names tagged to utterances), which is superior to post-hoc transcription from the audio file alone.

## Requirements

The meet app must:

1. Automatically receive webhook notifications from 8x8, download files from `RECORDING_UPLOADED`, `TRANSCRIPTION_UPLOADED`, and `CHAT_UPLOADED` events, and upload them to a Nextcloud instance via WebDAV before the 24-hour link expiry.
2. Log all authenticated webhook events (any event type) for observability.

### Prerequisites

The 8x8 JaaS webhooks must be registered in the 8x8 admin console before this feature can function:

- **Webhook URL:** `https://meet.lobb.ie/webhook/recording`
- **Events:** `RECORDING_UPLOADED`, `TRANSCRIPTION_UPLOADED`, `CHAT_UPLOADED`, plus any other events desired for logging
- **Authorization header:** a bearer token, stored in secrets config
- This is a one-time manual configuration step in the 8x8 JaaS dashboard.

## Solution

### Architecture

The webhook handler follows a simple pipeline: **receive → authenticate → log → validate → respond 200 → download → upload → clean up**.

All authenticated events are logged via structured JSON logging (slog). Events with a `preAuthenticatedLink` (`RECORDING_UPLOADED`, `TRANSCRIPTION_UPLOADED`, `CHAT_UPLOADED`) additionally trigger the async download/upload pipeline. All other events are logged and acknowledged.

### Config additions

New fields in the config/secrets YAML:

```yaml
# config/<host>.yaml
recording:
  webdav-path: "/Recordings/meet"    # destination folder on Nextcloud

# secrets/<host>.yaml (encrypted)
recording:
  webdav-url: "https://nextcloud.example/remote.php/dav/files/user"
  webdav-user: "user"
  webdav-password: "app-password"
  webhook-token: "random-bearer-token"
```

### Webhook endpoint

- `POST /webhook/recording` — accepts 8x8 webhook payloads
- Validates `Authorization` header against configured `webhook-token`
- Logs every authenticated event: event type, fqn, sessionId, timestamp
- For download events (`RECORDING_UPLOADED`, `TRANSCRIPTION_UPLOADED`, `CHAT_UPLOADED`):
  - Tracks `idempotencyKey` in an in-memory set (bounded, evicts oldest) to deduplicate
  - Responds HTTP 200 immediately
  - Spawns a goroutine for the download/upload pipeline
- For all other events: responds HTTP 200 after logging

### Download/upload pipeline (goroutine)

1. Extract `preAuthenticatedLink`, `fqn`, `startTimestamp`, `durationSec` from payload
2. Construct filename based on event type:
   - `RECORDING_UPLOADED`: `{room}_{YYYY-MM-DD}_{HHmm}_{duration}s.mp4`
   - `TRANSCRIPTION_UPLOADED`: `{room}_{YYYY-MM-DD}_{HHmm}_transcript.{ext}`
   - `CHAT_UPLOADED`: `{room}_{YYYY-MM-DD}_{HHmm}_chat.{ext}`
   (extension inferred from the download URL or Content-Type)
3. Download to a temp file (with explicit timeout — recordings can be large)
4. Upload to Nextcloud via HTTP PUT to `{webdav-url}/{webdav-path}/{filename}`
   - Basic auth with configured credentials
   - Create destination directory if it does not exist (MKCOL)
5. Remove temp file on success
6. Log outcome (success or failure with context)

### Deduplication

8x8 does not guarantee exactly-once delivery. An in-memory map keyed by `idempotencyKey` prevents reprocessing. The map is bounded (e.g., 1000 entries) and entries older than 24 hours are evicted. This is sufficient — the server is single-instance and events are rare.

### Libraries

- `net/http` — webhook handler, download, WebDAV upload (all standard HTTP)
- No external WebDAV library needed — PUT with Basic auth is sufficient
- `encoding/json` — payload parsing

### Anti-patterns to avoid (per CODING.md)

- No error suppression — all download/upload errors logged with full context
- No string-built URLs — use `url.JoinPath` or `path.Join`
- Explicit timeouts on all network operations (connect + read separately)
- No global mutable state — dedup map owned by the server struct
