## Original issue body

## Problem

The NixOS integration contract supplies `CONFIG_PATH` as the host-specific config path and requires the app to load `defaults.yaml` from the same directory as that path. The app must treat the host filesystem layout as an infrastructure detail and must not assume a repository checkout exists on the host.

Before this change, `meet` built its automatic config chain as:

```text
config/defaults.yaml,$CONFIG_PATH,$SECRETS_PATH
```

That works in local development and in legacy repo-checkout deployments, but it is not correct for deploy-nix hosts where the process working directory is not a source checkout and the deployed config directory is supplied through `CONFIG_PATH`.

## Solution outline

When `CONFIG_PATH` is set, derive the defaults path from its directory:

```text
$(dirname CONFIG_PATH)/defaults.yaml,CONFIG_PATH,SECRETS_PATH
```

When `CONFIG_PATH` is not set, preserve the local development fallback:

```text
config/defaults.yaml
```

Explicit `--config` values remain unchanged; the operator-provided chain is used as-is.
